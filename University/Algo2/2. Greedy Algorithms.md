<h4>Minimum Spanning Tree</h4>
Given a connected (undirected) graph G = (V,E) with positive rational edge weights w: E -> $\mathbb{Q}_{\geq0}$, an MST T = (V,F) is a spanning tree whose sum of edge weights minimised![[Pasted image 20250522005434.png]]
Spanning tree $\approx$ a subgraph of a graph that is a tree and spans (contains) all vertices of the graph
- A graph can have exponentially many spanning trees e.g., the complete graph K<sub>n</sub> on n vertices has n<sup>n-2</sup> spanning trees (Cayley's Theorem)
- Therefore it is not possible to solve the MST-problem by enumerating all possible spanning trees
- Fortunately there exists much more efficient algorithms for the problem that employ the greedy approach

Applications:
- Network Design
- Approximation algorithms for NP-hard problems
- Indirect Applications
	- max bottleneck paths
	- LDPC codes for error correction
	- reducing data storage in sequencing amino acids in a protein
- Cluster analysis
<h4>Greedy Algorithms</h4>

Greedy = Locally optimal choice at each step (Doesn't look at future only immediate benefit)

**Krusal's Algorithm**: Start with E(T) = $\theta$, consider edges in ascending order of weight, insert edge e in T unless doing so would create a cycle

Sorts edges by weight, then adds them one by one avoiding cycles

**Prim's Algorithm**: Start with some root node s and greedily grow a tree T from s outward, At each step add a cheapest edge e to T that has exactly one endpoint in T

Builds tree starting from one vertex and repeatedly adding smallest edge connecting tree to new vertex

Both algorithms produce MST

**Cut Property**: Let S be any subset of nodes, let e be minimum weight edge with exactly one endpoint in S, Then there is an MST that contains e

**Cycle Property**: Let C be any cycle and let f be a maximum weight edge belonging to C, Then there is an MST that does not contain f

<h4>Priority Queue</h4>
- Data structure that maintains set S of elements
- Each element v $\in$ S has associated value i, which describes its priority (in our case given by a[v])
- Smaller values represent higher priorities
Supported Operations (each runs in time at most O(log n))
- Insertion of element into S
- Removing of element from S
- Find element with smallest value (highest priority)
- Decrease priority of element

<h4>Kruskal's Algorithm</h4>
- Consider edges in ascending order of weight
- Case 1: If adding e to T creates cycle, discard e according to cycle property
- Case 2: Otherwise insert e = {u,v} into T according to cut property where S is set of nodes in u's connected component![[Pasted image 20250522011747.png]]

<h4>Dijkstra's Algorithm</h4>
Given:
- Directed graph D = (V,E)
- Length (weight/cost) function l: E -> $\mathbb{Q}_{\geq0}$
- Source (initial) vertex s

Problem: 
Find shortest directed path from s to every other vertex in D![[Pasted image 20250522012659.png]]
- Similar to BFS/Prim's
	- Grow set S of nodes for which you already computed shortest path from s
	- Always pick some vertex next that is closest to s among all nodes outside of S
- However because edges can have different lengths, finding next vertex becomes slightly more complicated

- Iteratively grow set of S of **visited vertices** for which we already calculated the length l(u) of shortest s-u-path
- Initialise S = {s}, l(s) = 0
- Choose vertex v that minimises the length of any shortest s-v path that uses only vertices in S $\lor$ {v}, i.e., v minimises the following value $$\underset{u\in S\ \text{and} \ v\in N^+(u)}{min} \ l(u)+w(u,v)$$
- Add v to S, set l(v) = $\underset{u\in S\ \text{and} \ v\in N^+(u)}{min} \ l(u)+w(u,v)$ and continue with previous step

<u>Improvement</u>

To avoid having to recalculate $\underset{u\in S\ \text{and} \ v\in N^+(u)}{min} \ l(u)+w(u,v)$ at each step of algorithm and for all vertices outside of S, one can remember the previous values and only update values if a new vertex is added to S, i.e.:
- One initially sets S = $\theta$, l(s) = 0 and l(v) = $\infty$ for every v $\in$ V \\{s}
- Every time vertex v is added to S one sets $$l(x)=min\{{l(x),l(v)+w(v,x)}\}$$ for every vertex x $\in$ N<sup>+</sup>(v) \ S,
- next vertex to be added to S is then always vertex that minimises l(v) among all vertices outside S

Consider two data structures for computation of set S:
- Simply-linked list
- Priority queue, for notes outside of S ordered w.r.t to length l. An entry in the queue consists of node-index and its currently associated length![[Pasted image 20250522015112.png]]
