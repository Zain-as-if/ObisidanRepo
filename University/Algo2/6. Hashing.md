Alternative data structure for dictionary problem 
Observation: Usually only small subset of all possible keys is stored
Idea: Instead of searching through set of data elements using key comparisons, **one can calculate the (exact) position** of an element in storage (usually array) **by using arithmetic operations**
![[Pasted image 20250522232226.png]]
Hash Table:
- Assume that the hash table T has fixed size m and uses an array with indices 0,...,m-1
- For hash table of size m that currently stores n keys (elements), denote by $\alpha=\frac{n}{m}$ its **load factor**
Hash function:
- We chose hash function $h:\kappa\rightarrow\{0,\dots,m-1\}$ that assigns every key $k\in\kappa$ a unique hash value (however, more than one key can be assigned the same hash value)

Advantage:
runtime for operations search, insert and remove is constant $\theta(1)$ in **ideal case** and assuming that h(s) can be calculated in constant time

Limitations:
- whenever $h(k)=h(k')$ for $k\neq k'$, i.e. two distinct keys obtain same hash value, we say we have a **collision**
- $\theta(1)$ only holds if we assume that the number of collisions is neglectable, usually only achievable for the expected value
- Worst case runtime still O(n)

<h4>Hash Functions</h4>
Good hash function:
- Aim is a uniform distribution of used keys to buckets 0,...,m-1 of hash table
- Small changes to keys should lead to distinct and possibly independent hash value
