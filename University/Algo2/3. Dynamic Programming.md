**Dynamic Programming**: Divide the problem into a sequence (hierarchy) of (overlapping) subproblems and compute and store solutions for larger and larger subproblems with the help of saved solutions 

**Bellman's Principle Of Optimality**: Optimal policy (set of decisions) has the property that whatever the initial state and decisions are, remaining decisions must constitute and optimal policy with regard to the state resulting from the first decision

**Efficiency**: Depends on the approach used when dividing and computing the solutions for the sub-problems

Algorithms:
- Bellman-Ford & Floyd-Warshall
- Efficient method for knapsack problem
- CYK-Algorithm for parsing context-free grammars
- O<sup>*</sup>(2<sup>n</sup>)-Algorithm for Travelling Sales person problem

Given dimensions d<sub>0</sub>,d<sub>1</sub>, ..., d<sub>n</sub>, want to compute minimum number of scalar multiplications needed to multiply matrices

Let M\[i]\[j] be minimum number of scalar multiplications needed to compute the product $A_{i}A_{i+1}...A_{j}$

For 1<=i<=k<=n let M\[i,k] denote minimum number of scalar multiplications to compute $A_{i}......A_{k}$ 

M\[i,i] = 0, for all i with 1<=i<=n

<h4>Shortest Paths (w/ Negative Weights)</h4>
Input: Directed graph G = (V,E), edge-weights $w: E \rightarrow\mathbb{Q}$ 

Definition:
Shortest-path algorithm typically refers to problem of finding minimum-weight/length path between two or some vertices of graph

Will sometimes assume that w is defined on V x V by setting w(v,v) = 0
for every $v \in V$ and w(u,v) = $\infty$ for every u,v $\in$ V with (u,v) $\notin$ E 

Weight/length of path P = ($v_{1},v_{2},...,v_{k}$) given by: $$w(P) = \sum^{k-1}_{i=1}w(v_{i},v_{i+1})$$
Shortest-path weight/length from some vertex u to v is defined as: 
$$\delta(u,v) = \begin{cases}
min\{w(P)|u\leadsto^P v\}, & \text{if there is a path from u to v} \\
\infty & \text{otherwise}
\end{cases}$$
$u\leadsto^P v$ : "**P is a path from u to v**"

<u>Problem Variants</u>
- No weights (or w(e) = 1 for all e $\in$ E) => BFS
- No negative weights => Dijkstra
- Weighted digraphs with negative weights
- In case of no negative edge weights same algorithms applicable to undirected graphs (replace edges by two arcs; set w(u,v) = w(v,u))

\[SPSP] **Single pair shortest path problem**
- Find shortest path from s to t 
\[SSPP] or \[SSSP] **Single source shortest path problem**
- Single source or target vertex v is specified, find shortest paths from v to every other vertex u $\in$ V \ {v}
\[APSP] **All Pairs shortest path problem**
- Find shortest path from s to t for every s,t $\in$ V

NOTE: no algorithms  known that run asymptotically faster than best SSPP algorithms

Theorem: Finding shortest path in directed graph with negative weights is NP-Complete, i.e., unlikely to be solvable in polynomial time
Remark: If no negative cycles exist the problem can be solved in polynomial time

Can't use Dijkstra's algorithm, fails for negative edge weights
Can't add constant to every edge weight to make positive 

<u>Overview</u>

1. Dijkstra's Algorithm \[SSSP]
	- Non-negative weights, Fibonacci Heaps O($n\log (n+m)$)
2. Bellman-Ford Algorithm \[SSSP]
	- Negative weights allowed, O(nm)
3. Matrix-Multiplication Algorithm \[APSP] 
	- $O(n^\alpha \log n)$ where $O(n^\alpha)$ is time to multiply two n x n matrices, 2<=$\alpha$<=3
4. Floyd-Warshall Algorithm \[APSP] 
	- Negative weights allowed, O(n<sup>3</sup>)
5. Johnson's Algorithm \[APSP]
	- Negative weights allowed, $O(n^2\log (n+nm))$ 
Except Dijkstra's algorithm, all algorithms based on dynamic programming

To compute distance between every pair of vertices in edge-weighted graph, we can run SSSP algorithm for every start vertex, However better ways:
- Matrix Multiplication
- Floyd-Warshall Algorithm
<h4>Matrix-Multiplication Algorithm</h4>
Let $\delta^{(m)}_{i,j}$ be length of shortest path from i to j, subject to the condition that path contains no more than m arcs, we have:$$\begin{align} \delta^{(0)}_{i,i}  = 0 \\ \delta^{(0)}_{i,j}=\infty, (i\neq j) \\ \delta^{(m+1)}_{i,j}=\underset{k}{min}\{\delta^{(m)}_{i,k}+w(k,j) \} \end{align}$$

<h4>CYK Algorithm</h4>
Cocke-Younger-Kasami (CYK) algorithm is a parsing algorithm for context-free grammars (CFGs) in Chomsky normal form (CNF)

Determines whether a given string can be generated by a context-free grammar and optionally builds a parse tree. Used in syntax analysis especially in compilers.

CFG - set of rules (productions) that describe all possible strings in a particular context-free language

CNF - restricted form of CFG where each production is either:
1. A -> BC, 2 non-terminals
2. A -> a, single terminal
3. S -> $\epsilon$, only allowed if language includes empty string

CFGs in Chomsky normal form:
Let G = (V,T,P,S) be a CFG in CNF that is:
- V is a finite set of **variables**, or non-terminals
- T is a finite set of **terminals**, $V \land T = \theta$
- $P \subseteq V \times ((V \times V)\lor T)$ is the set of **productions**
- $S \in V$ is the **start symbol**
Since G is in CNF, productions are of the form:
A -> BC or A -> a or S -> $\epsilon$ 
for A,B,C $\in$ V and a $\in$ T, and where $\epsilon$ denotes the empty string

If production S -> $\epsilon$ belongs to the grammar, then S cannot occur on the right hand side of a production
