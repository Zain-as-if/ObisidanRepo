<h4>Undirected Graphs</h4>
G = (V,E)
- V set of vertices (nodes)
- E set of edges between pairs of vertices
- captures pairwise relationships between objects
- notation for edges between vertex *a* and vertex *b*: {a,b}/{b,a}
- alternatively also ab/ba or a-b/b-a
- graph size parameters/notation: n=|V|, m=|E|
![[Pasted image 20250521154928.png]]
adjacent, incident, neighbourhood:
Let *e = {u,v}* be an edge in *E*
- *u* and *v* **adjacent**, i.e. *u* is a **neighbour** of *v* and *v* is a neighbour of *u*
- *N(v) = {w|{v,w}$\in$E}* is the **open neighbourhood** of *v*
- *N\[v] = {v}$\lor$N(v)* is the **closed neighbourhood** of *v*
- *v* (respectively, *u*) and *e* are **incident**
- {u,v} = {v,u}
degree:
deg(v) denotes the **degree** of the vertex *v* 
- deg(v) = to the number of edges incident to *v*
- We have $$\sum_{u\in V} deg(v) = 2 \cdot |E|$$
Multi-edge: More than one edge between same two vertices
Loop: Edge between a vertex and itself

Simple graph: Undirected graph without multi-edges and loops
<h4>Directed Graphs</h4>
G = (V,E) 
- V set of vertices (nodes)
- E set of **arc** (directed edges) between pairs of vertices
- notation for arc from a to b: (a,b)/a->b
- (a,b)$\neq$(b,a)
![[Pasted image 20250521160446.png]]
Let a = (u,v) be an arc in E then:
- v is the **head** and u is the **tail** of a
- u is an **incoming neighbour** of v and v is an **outgoing** neighbour of u
- N<sup>-</sup>(v) is set of **incoming neighbours** of v, i.e., N<sup>-</sup>(v) = {u:(u,v)$\in$E}
- N<sup>+</sup>(v) is set of **outgoing neighbours** of v, i.e., N<sup>+</sup>(v) = {u: (v,u)$\in$E}
- deg<sup>-</sup>(v) is **in-degree** of v, i.e., deg<sup>-</sup>(v) = |N<sup>-</sup>(v)|
- deg<sup>+</sup>(v) is **out-degree** of v, i.e., deg<sup>+</sup>(v) = |N<sup>+</sup>(v)|
we have: deg(v) = deg<sup>+</sup>(v) + deg<sup>-</sup>(v)

<h4>Adjacency Matrix</h4>
N-by-N matrix with A<sub>uv</sub> = 1 if {u,v} is an edge
- Vertices: 1,2,...,n
- Two representations of each edge
- Space proportional to n<sup>2</sup>
- Checking if {u,v} is an edge takes $\theta$(1) time
- Identifying all edges takes $\theta$(n<sup>2</sup>) time
![[Pasted image 20250521171954.png]]
<h4>Adjacency List</h4>
Node indexed array of lists
- Vertices: 1,2,...,n
- Two representations of each edge
- Space proportional to m+n
- Checking if {u,v} is an edge takes O(deg(u))
- Identifying all edges takes $\theta$(m+n) time 
![[Pasted image 20250521172922.png]]Number of edges:
- Graph can have up to $\begin{pmatrix}n \\ 2\end{pmatrix} = \frac{n(n-1)}{2}=O(n^2)$ edges
- for such dense graph both representations use same amount of space and are comparable
Practice:
- graphs coming from applications are usually much less dense
- often m = O(n)
- in these cases, representation via adjacency lists preferable

<h4>Paths</h4>
**Path** in an undirected graph G = (V,E) is a sequence
($v_{1},v_{2},\dots,v_{k-1},v_{k}$), k>=1 of vertices with the property that each consecutive pair $v_{i}, v_{i+1}$ is joined by an edge E
**Length** of a path is k-1 
![[Pasted image 20250521180237.png]]
Can also say that path goes from $v_{1}$ to $v_{k}$  and that path is a v<sub>1</sub>-v<sub>k</sub>-path

Vertex u is **reachable** from a vertex v in G, if G contains an u-v path
An undirected graph is **connected**, if for every pair u and v of vertices, there is a path between u and v

Shortest u-v path between two vertices u and v is a path between u and v of shortest length. Shortest path always **simple**, i.e., no vertex occurs twice on the path

**Distance** between vertices u and v in undirected graph is the length of a shortest u-v path

If u is not reachable from v, assume distance to be $\infty$   

**Cycle** is a path ($v_{1}, v_{2},\dots,v_{k-1},v_{k}$) for which {$v_{1},v_{k}$} is edge too, k>=3
The **length** of this cycle is k
![[Pasted image 20250521180614.png]]
**Path** in digraph G(V,E) is sequence ($v_{1}, v_{2},\dots,v_{k-1},v_{k}$), k>=1 of vertices with property that every consecutive pair $v_{1},v_{k+1}$ is connected by a directed arc from v<sub>k</sub> to v<sub>k+1</sub> 
- Path goes from start vertex to end vertex, reverse may not necessarily hold
- v can be reached from u, if there is u-v-path
- shortest u-v-paths are **simple**
**Cycle**: directed cycle is path ($v_{1}, v_{2},\dots,v_{k-1},v_{k}$) with u<sub>k</sub>->u<sub>1</sub>, k>=2
<h4>Tree</h4>
Undirected graph is a **tree** if connected an acyclic (i.e., doesn't contain cycle)

Theorem: Let G be undirected graph with n vertices, every two of following conditions imply the third:
- G is connected
- G does not contain cycle
- G has n-1 edges
Properties of trees:
- **leaf** is a vertex of degree one
- every tree with at least 2 vertices has at least one leaf
- there is a **unique** path between any two vertices in a tree

**Rooted Tree**: Obtained from a tree by choosing an arbitrary vertex r as root and directing all edges away from r

<h4>BFS</h4>
Explore outward from start vertex s in all possible directions, adding nodes one 'layer' at a time

Algorithm:
- $L_{0}$ = {s} 
- $L_{1}$ = all neighbours of vertices in $L_{0}$ 
- $L_{2}$ = all vertices that are not in $L_{0}$ or $L_{1}$ and that are adjacent to a vertex in $L_{1}$ 
- $L_{i+1}$ = all vertices that are not in any previous layer and that are connected via an edge to a vertex in $L_{i}$ 
$L_{i}$ contains all vertices of distance i from s for every i

Proof:
Let ($v_{0}, v_{1}, v_{2},\dots,v_{n}$) be a shortest path between $v_{0}$ and $v_{n}$
- $v_{0}$ is in $L_{0}$
- $v_{1}$ is in $L_{1}$, since $v_{1}$ is a neighbour of $v_{0}$ 
- $v_{2}$ is in $L_{2}$ since $v_{2}$ is a neighbour of $v_{1}$ and not a neighbour of $v_{0}$ (otherwise there would be a shorter path between $v_{0}$ and $v_{n}$ using edge between $v_{0}$ and $v_{2}$)
- Argument applies for all other vertices which implies that $v_{i}\in L_{i}$ for every i
![[Pasted image 20250521182034.png]]
BFS has run-time of O(n+m)
Run-Time: (need to consider 3 parts)
- Initialisation
- While-loop
- For-loop (inside while-loop)

**Initialisation**:
- Every vertex considered once
- constant time per vertex
- Therefore, run-time for initialisation is O(n)
**While-loop**:
- Every vertex is adding to Q at most once, since it will be marked visited thereafter 
- Therefore, every vertex considered only once in while-loop
**For-loop**:
- Let u be current vertex before entering the for-loop
- Then all neighbours of u are considered in the for-loop
- Therefore, the for-loop is executed exactly deg(u) times with each execution requiring only constant time
Total:
- Total run-time therefore $$O(n+\sum_{u\in V}deg(u))$$
- Since above $\sum_{u\in V}deg(u)$= 2m, obtain run-time of O(n+m)

**BFS-Tree**: BFS creates a tree whose root is start vertex s containing all vertices reachable from s 

**Creation**: Starting at s, whenever vertex v is visited for first time as a neighbour of a vertex u, becomes the child of u in the BFS-Tree

Property: 
Let T be a BFS-Tree of G = (V,E) and let {x,y} be an edge of G. Then the level of x and y in T can differ by at most one ![[Pasted image 20250521182722.png]]
<h4>DFS</h4>
From visited node go first to another not yet visited neighbour (recursive call) before visiting other neighbours 
![[Pasted image 20250521182854.png]]
DFS runs in time O(n+m)
Run-time: (need to consider)
- Initialisation
- For-loop

**Initialisation**:
- Takes time O(n)
- DFS(G,v) is called at most once per node
**For-loop**:
- Considers all deg(v) nodes n in adjacency list of v
- therefore for-loop executed deg(v) times
- all commands within the for-loop take constant time (apart from recursive call of DFS(G,v) whose run-time considered in analysis for node v)
Total:
- Therefore total run-time is $$O(n+\sum_{u\in V}deg(v))$$
- Since $\sum_{u\in V}deg(u)$ = 2m, we obtain O(n+m)

**DFS-Tree**: Start at s, whenever vertex v is visiting for the first time as a neighbour of a vertex u it becomes the child of u in the DFS-Tree

Property:
- Edges of graph must be between vertices on same root-to-leaf path
- Edges of graph must not be between different branches of DFS-Tree

<h4>DFS vs. BFS</h4>
Search order, DFS differs from BFS:
- One first tries to get as far away from the start node as possible
- Once there are no unvisited nodes left in neighbourhood, recursion backtracks to find first node having an unvisited neighbour
- Edges in the graph only go between ancestors and descendants in the DFS-Tree but can jump levels in the tree![[Pasted image 20250521183432.png]]
<h4>Connected Components</h4>
**Connectivity**: undirected graph is **connected** if there is a path between every pair of nodes in the graph

**Disconnected**: If the graph contains a pair of nodes without a path between them, graph is not connected 

**Sub-Graph**: A graph G<sub>1</sub> = (V<sub>1</sub>,E<sub>1</sub>) is a **subgraph** of a graph G<sub>2</sub> = (V<sub>2</sub>,E<sub>2</sub>), if V<sub>1</sub> $\subseteq$ V<sub>2</sub> and E<sub>1</sub> $\subseteq$ E<sub>2</sub> (V1 is subset of V2, Same with E)

**Connected Component**: Maximal connected subgraph of graph is called a **connected component**, Disconnected graph is the disjoint union of its connected components![[Pasted image 20250521184048.png]]
To identify connected components: Find all nodes that can be reached from s
Solution: 
- call DFS(G,s) or BFS(G,s)
- Node u is reachable from s if and only if visited[u]=true

Counting Connected Components:
Run-time: O(n+m)
Analysis:
- Let G = (V,E) be given graph and G<sub>1</sub> = (V<sub>1</sub>,E<sub>1</sub>),...,G<sub>r</sub> = (V<sub>r</sub>,E<sub>r</sub>) its connected components
- Let |V| = n, |E| = m, and |V<sub>i</sub>| = n<sub>i</sub> and |E<sub>i</sub>| = m<sub>i</sub>, for every i with 1<=i<=r
- Clearly n = n<sub>1</sub> + ... + n<sub>r</sub> and m = m<sub>1</sub> + ... + m<sub>r</sub>
- For every connected component G<sub>i</sub>(1<=i<=r) the algorithm performs DFS, this has runtime O(n<sub>i</sub> + m<sub>i</sub>)
- Initialisation requires O(n) time
- Therefore obtain $$O(n+\sum^r_{i=1}(n_{i}+m_{i}))=O(2n+m)=O(n+m)$$
<h4>Search In Directed Graphs</h4>
**Directed Reachability**: Find all nodes that can be reached from given node s

**Directed shortest s-t path**: Find shortest path from s to t, for two given nodes s and t

**Search in directed graphs**: BFS and DFS can be applied for directed graphs

Two nodes u and v **strongly connected** if there is a path from u to v and vice versa
![[Pasted image 20250521185034.png]]
Directed graph **strongly connected** if every pair of nodes strongly connected

Directed graph called **weakly connected** if underlying undirected graph (i.e. undirected graph that one obtains by ignoring the direction of edges) is connected ![[Pasted image 20250521185211.png]]
**Lemma**
Let s be arbitrary node in directed graph G. G strongly connected if and only if every node can be reached from s and every node can reach s

Proof:
- Follows from definition
- Path from u to v: combine a u-s path with s-v path 
- Path from v to u: combine a v-s path with s-u path
- Paths might and are allowed to overlap

Algorithm:
Testing whether G is strongly connected can be achieved in O(n+m) time
Proof:
- Choose arbitrary node s
- Execute BFS with start node s in G
- Execute BFS with start node s in G<sup>rev</sup>
- Return yes if and only if all node scan be reached in both executions of BFS above
- Correctness follows immediately from previous lemma
- G<sup>rev</sup> obtained from G by reversing direction of every arc in G
<h4>Directed Acyclic Graph (DAG)</h4>
Directed graph with no directed cycles

**Topological ordering** of a directed graph G = (V,E) is a linear order of its nodes, denoted by $v_{1},v_{2},\dots,v_{n}$ such that i\<j for every arc ($v_{i},v_{j}$) 
![[Pasted image 20250521185813.png]]
**Ordering Constraints**: arc (u,v) means that task u needs to be achieved before task v

Applications:
- Preconditions for modules: module u has to be complete before module v
- Compilation: class u has to be compiled before class v
- Pipeline between processes: output of process u required for input to process v
<h4>DAG</h4>
Lemma: If G has topological ordering then G is a DAG
Proof (contradiction):
- Assume G has topological ordering $v_{1},\dots,v_{n}$ and contains directed cycle C
- Let v<sub>i</sub> be node with smallest index in C and let v<sub>j</sub> be node before v<sub>i</sub> in C i.e., there is arc (v<sub>j</sub>,v<sub>i</sub>)
- Due to choice of i, holds that i\<j
- On other hand, because (v<sub>j</sub>,v<sub>i</sub>) is arc and $v_{1},\dots,v_{n}$ is topological ordering, should be the case that j\<i, Contradiction![[Pasted image 20250521190523.png]]
![[Pasted image 20250521190632.png]]![[Pasted image 20250521190637.png]]
Algorithm finds topological ordering in time O(n+m)
Proof: (consider following parts)
- Initialisation
	- First for-loop for count
	- Second (nested) for-loop
	- Third (for-loop) for generating Q
- While-loop (with nested for-loop)

**Initialisation**:
- First for each-loop which initialises count, takes time O(n)
- For second nested for-loops: inner loop executed deg<sup>+</sup>(v) times for every node v, takes time O(n+m)
- Third for-loop for generating Q takes time O(n)
- Therefore initialisation requires time O(n+m)
**While-loop**:
- Every node v is removed at most once from Q
- Therefore, while-loop executed at most once per node
**For-Each loop**:
- Let v be currently active node before for-loop executed
- Then for-loop executed once for every outgoing neighbour w of v
- Those exactly deg<sup>+</sup>(v) many, therefore for-loop executed deg<sup>+</sup>(v) times and single commands inside for-loop take constant time
- Every node w is added at most once to Q
Total:
- Initialisation O(n+m)
- While-loop O(n+m)
- Therefore O(n+m) total runtime

- Start DFS at first unvisited vertex
- Follow only outgoing edges, i.e., replace N(v) by N<sup>+</sup>(v)
- Number a vertex (decreasing order) after all its out-neighbours are numbered
- Repeat until no unvisited vertices left
