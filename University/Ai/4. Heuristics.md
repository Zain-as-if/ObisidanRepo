Rule of thumb - Good way of evaluating something which is not theoretically perfect

Heuristic functions are used to compute estimates to guide the choices of nodes to expand

Typically use an heuristic function that estimates the cost of getting from any given state to a goal state, i.e cost of remaining goal path. Thus we want a function that gives a low value for states that we think are likely to be near the solution and a high value for those that are far from the solution

Use of heuristics gives us a new way to guide a search algorithm that was not available with uninformed search. Heuristic function gives an indication of which nodes are likely to be the 'best' choices in the search for a solution. 

In queue-based search, heuristics can be used to order the nodes in the queue, called **best-first** search

Since heuristic only gives an estimate of how close a node is likely to be to the solution, will not always tell us which is actually best. 

<h4>Greedy Search</h4>
Simplest 'best-first' search algorithm simply orders the node queue according to the heuristic function 

Always expand the node with the lowest value of the heuristic

Children of the expanded node are then merged into the queue according to the heuristic function ordering

Properties:
- Susceptible to 'false starts' and other inefficient behaviour 
- Incomplete - If infinite branches, may carry on forever, never trying alternatives that were rates less good by heuristic but lead to solution
- Non-optimal - no guarantee of finding lowest cost solution
- Time & Space complexity are both b<sup>n</sup>, where b is branching factor and n is maximum depth of search tree
<h4>A* Search</h4>
Clever but simple algorithm avoids problems of greedy search. Does this by taking account the cost expended in getting to a node (like uniform cost)

Expand nodes in order of lowest value of the heuristic f(n):
$$f(n) = c(n) + h(n)$$
where:
- c(n) - cost of getting from initial state to node n
- h(n) - heuristic estimate of the cost of getting from node n to goal state
Thus f(n) gives estimate of the total cost of getting from initial state to goal state 

Provided with an admissible heuristic, A* nice properties,

Properties:
- Complete - Always finds solution if one exists
- Optimal - Will always find a minimum cost path to solution 
- Time & Space Complexity - Both exponential in solution path length

Admissibility is required for these properties as it ensures that no node is ignored because it is considered further from the solution than it actually is. 

A heuristic *h* is admissible if its estimate *h(n)* of the cost to get from the node *n* to a goal state is always less than or equal to the actual cost of the minimum path from *n* to a goal state.

Admissible heuristics often described as **optimistic** since they tend to indicate the goal is closer than it actually is. 

<h4>8-Puzzle Example</h4>
8-puzzle is a 3x3 grid, one space empty. A move consists of sliding one of the tiles into the empty space. ![[Pasted image 20250517154001.png]]
2 relatively straightforward heuristics one can apply:
1. h(state) = no. of tiles in state that are not in the place they should be in the goal state
2. h(state) = the sum of **Manhattan Distances** from the position of each tiles in state to its position in the goal state

The **Manhattan Distance** is the sum distances in the horizontal and vertical directions.
<h4>Evaluating Heuristics</h4>
Calculate their **Effective Branching Factor** over a set of problems by comparison with BFS. 

In BFS the no. of nodes *N* generated in exploring a search tree with branching factor *b* to a depth *d* is given by:
$$N = 1 + b + b^2 + \dots + b^d$$
If we use some heuristic function, this equation is not applicable, but we will still have values for *N* and *d* for each successful search

From these we use the above formula to calculate the **Effective Branching Factor** *b*, as if we were using ordinary BFS. By averaging over a number of problems we get a good measure of the heuristic (closest to 1 is best). 

If *h1* and *h2* are two heuristics for the same problem and for all states *s* we always have *h2 >= h1* we show that *h2* dominates *h1*.

For admissible heuristics the dominant heuristic is always better. 

Since the heuristics don't overestimate the distance to the goal, a higher value is always closer to the true distance - hence more accurate. More accurate heuristics give better guidance towards the goal.

Good way of finding a heuristic is by considering a distance measure for simpler, less constrained version of the problem.

E.g 8-puzzle can be considered as the problem of moving tiles from one grid configuration to another under the following conditions:
- Only one tile can move at a time
- A tile can only move one space at a time
- A tile can't move on top of another tile

By relaxing (i.e removing) one or more constraints in a problem, we get problems where the distance to the goal is exactly given by one of the 8-puzzle heuristics (no. misplace tiles, total Manhattan distance)
<h4>Iterative Improvement Algorithms</h4>
Solution always been cast as a sequence of steps to a goal. In cases where only the goal is important we have considered steps that build towards a complete solution in stages. 

Alternative approach to finding a solution is **iterative improvement**, basic idea is: 

Start with a complete (but defective / sub-optimal) state configuration and make modifications to improve its quality.

When doing iterative improvements, normally use a heuristic that is **positive** measure of 'goodness' of each state (high is good), hence we look for modifications that **increase** the value of the heuristic.

Iterative improvement can also be used for constraint satisfaction type problems

In such cases we allow states to violate certain constraints and then define a heuristic that measures how good a state in terms of the no. of constraints that are violated

For instance in the N-Queens problem, we can use a heuristic based on the no. of 'clashes' arising in a state - i.e no. of queens that lie on a taking move of another queen

Iterative improvement would then proceed by looking for ways to move one of the queens that reduces the no. of clashes.
