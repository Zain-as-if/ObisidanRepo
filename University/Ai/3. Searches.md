<h4>Breadth-First Search</h4>
Start at the root and explore the tree by working our way down **level-by-level**. Testing each path to see if we have reached a goal![[Pasted image 20250515223847.png]]

<h4>Depth-First Search</h4>
Follow a single path down as deep as we can go until either reach a goal or dead end. If we reach dead end, can 'backtrack' up the path until we reach a branch that has not yet been tried.![[Pasted image 20250515223947.png]]

Typically we assign a cost to each transition, and the cost of a path is simply the sum of the costs of each transition in the path. 

<h4>Properties Of Search Problems/Spaces</h4>
- Branching factor: No. of successor nodes
- State space may be finite or infinite
- Paths through the space may or may not have loops
- Maximum path length may be bounded or unbounded 
<h4>Properties Of Search Algorithms</h4>
- Completeness: Is the algorithm guaranteed to find a solution if one exists?
- Time Complexity: How much time does the algorithm require in relation to the depth of the solution?
- Space Requirements: How much memory does the algorithm require in relation to the depth of the solution?
- Optimality: Is the algorithm guaranteed to find the best solution?
 
<h4>Implementation Techniques</h4>
- Explicit representation of node set and implementation of choice algorithm for node expansion 
- Recursive algorithm, nodes are not represented explicitly but are explicitly in the execution sequence of the algorithm 
<h4>Nodes & Node Expansion</h4>
All standard search algorithms treat the search space as a tree. Each node in the tree corresponds to a state. Each node (except root) has a parent and 0 or more children. The children are nodes that are reachable by one action.

Node expansion is the process of computing the children of a given node. Often done in 2 stages:
1. Determine what actions are possible
2. Determine the successor state that results from each of these actions

The **fringe** is the set of nodes that have been generated by the search procedure, but have not been expanded.

The **search strategy** can be characterised as the method by which an algorithm chooses which of the fringe nodes to expand.

When a node is expanded it is no longer part of the fringe. But its children are then added to the fringe.

<h4>Node Queueing</h4>
One way to control the way in which fringe nodes are chosen for expansion is to organise the fringe nodes as a **queue**, i.e a list of nodes from which we draw from one end

Search using a queueing system proceeds according to the following repeated sequence:
- Take first node from the queue
- If the node satisfies the goal, return the node (search successful)
- Otherwise, expand the node to find its children
- Add the children to the queue
If the queue becomes empty the search fails

<h4>Depth First</h4>
Modifications: 
- Depth Limited
- Iterative Deepening
Often used with loop checking and/or random brand choice

Properties:
- Relatively modest memory requirements (*∝* path length to solution), we only need to store nodes in a single active branch
- Not usually optimal, often explores branches that are much longer than the shortest to a solution 
- Not complete unless all paths terminate
- Loop checking is often required to eliminate useless infinitely repeating branches
- Can be implemented by a LIFO Node-Queueing System, i.e add generated child nodes to the **front** of the queue
<h4>Breadth First</h4>
Modifications:
- Uniform Cost (not exactly breadth-first)
- Bi-Directional Search
Can be combined with removal of duplicate states and other node pruning techniques 

Large memory requirement, since the no. of nodes in the fringe is of the order of b<sup>d</sup>
where b is the (average) branching factor, and d is the depth of the tree.

Properties:
- Complete as long as branching factor is finite
- Finds the shortest path to a goal first. For problems where each step has the same cost, this will also be an optimal path
- Execution time increases exponentially as the minimum path length to solution increases
- Memory requirements can be very large. Need to store the whole tree down to the level of the solution, memory exponential function of minimum path length to solution
- Can be implemented by a FIFO Node-Queuing System, i.e add generated child nodes to the **end** of the queue
<h4>Depth-Limited Search</h4>
Major problem with Depth-First search is that it is **incomplete** unless every branch is eventually terminated either by:
- Reaching goal or dead end
- Looping to state that occurs earlier in the branch (need to test for this)

If there are non-terminating branches, the search may run forever without either reaching goal state or determining that the problem is insoluble 

In depth-limited search we set maximum length of path that will be searched. Still usually incomplete (unless some reason why there must be a solution with a path within the limit), however at least the search algorithm guaranteed to terminate
<h4>Iterative Deepening</h4>
Consists of repeated use of depth-limited depth-first search where depth-limit is increased (by one or more) each time until solution is found. 
Combines benefits of breadth and depth-first search:
- Modest memory requirements (same as depth-first)
- Complete when branching factor is finite
- Optimal when path cost is non-decreasing function of depth
Downside is that execution time likely to be large

<h4>Uniform Cost Search</h4>
Variant of Breadth-First search.
In standard BFS, always expanding nodes closest to the initial state in terms of no. of actions in their path. In UC search we expand the nodes that are closest to the initial state in terms of the **cost** of their path. Hence, nodes on the fringe will have similar costs.

UC search will find the optimal (minimum cost) path first, provided that path cost is a monotonically increasing function of depth.

If cost of all actions is the same, UC search is equivalent to standard BFS. UC search can be implemented by a queue that is ordered by means of the path cost function (lowest cost first).
<h4>Direction Of Search</h4>
Sometimes better to search backwards from goal state to initial state.
Start from goal state and then look for states that can reach the goal by one action. Then proceed to look at states that can reach these states by one action, and continue until we reach initial state.

Useful for when the backwards branching factor is lower than forwards branching factor. 

Backwards search difficult to implement if there are many goal states, or if state transitions are difficult to define in the reverse direction. 
<h4>Bi-Directional Search</h4>
Search space is explored from both initial and goal state. Solution is found when the forward and backwards search paths meet at some state.

Advantages:
- Faster than unidirectional search: O(b<sup>d</sup>), bi-directional: O(b<sup><sup>d</sup>/<sub>2</sub></sup>)
- Effective in undirected graphs where path from start to goal is symmetric and goal is known
- Improved memory efficiency sometimes as each search front expands only half the depth
Disadvantages:
- Requires goal to be known
- Difficult to implement
- High memory usage in practice as both searches may store large sets of visited nodes
- Meeting point detection can be expensive as it requires checking whether nodes visited from one direction have been visited by the other
- Limited use in directed graphs, less effective if the graph is directed and the reverse path (goal to start) doesn't exist or is unknown
