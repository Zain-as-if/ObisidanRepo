Typical Example Of Search:
- Puzzles e.g Mazes, Rubiks Cube, Number Grid
- Route finding, motion control
- Activity planning, games AI (bots)
- Scheduling
- Mathematical problem solving
- Design of computer chips, drugs, buildings

E.g Maze:
To solve the maze we must find a **path** from an initial location to a goal location. 
A path is determined by a sequence of choices. At each **choice-point** we must choose between two or more **branches**.

In this maze example, search takes place within a physical space. We want to find a path connecting physical locations. We can apply the general idea of search to more abstract kinds of problems. To do this we replace physical space with a **state space**.

The states in the space can correspond to any kind of configuration. For example, the possible settings of a device, positions in a game, a set of assignments to variables (more abstract). 

Paths in state space correspond to possible sequences of **transitions** between states.

<h6>State Space</h6>
- Represents all possible states of a problem and the transitions between those states. Each node corresponds to a specific state, and edges represent the action that leads from one state to another
- Used to explore all possible configurations of a problem to find a solution. Common in puzzles, games and other decision-making scenarios

<h4>Search Space</h4>
Essentially just a state space, in which we have **initial state** and one or more **goal states**.

Given a search space, a solution to the search problem is a path consisting of a sequence of connected states, starting at the initial state and ending at one of the goal states.

- Broader concept than **state space**, includes all possible choices or decisions that can be made in a problem-solving process. Each node represents a choice, and the edges represent the possible subsequent choices
- Used to systematically explore the options available to find an optimal solution. This is commonly applied in optimisation problems, combinatorial problems and algorithms like backtracking. 

<h4>Differences Between Search & State Space</h4>
1. Focus:
	- State Space: Focuses on states & transitions between states
	- Search Space: Focuses on decisions and choices leading to different outcomes
2. Applicability:
	- State Space: More applicable to problems with defined states and actions (e.g games, puzzles)
	- Search Space: More applicable to combinatorial & optimisation problems where the choices are not strictly defined by states.
3. Structure: 
	- State Space: Often more structured, as it reflects the specific states of a system
	- Search Space: Can be more flexible, as it may not be limited to states and can encompass a wider range of decision-making processes

<h5>Types of Search Problem</h5>
Find a solution:
Search for a state or configuration satisfying known conditions. E.g scheduling, lecture A can't be the same time as lecture B

Find a plan or path leading to solution/goal:
Search for sequence of steps (actions) that lead from an initial state to a desired goal state (either specific or any state satisfying given goal conditions)

Find optimal solution:
If problem has multiple solutions, may be a preference of some solutions being better than others. If so, naturally interested in finding best solution

Find an optimal path to a goal:
Optimal sequence is one that has the lowest 'cost' (i.e takes the least time or resources). In many cases we will consider the optimal solution to be the one that is achievable with the least cost (i.e evaluate the solution in terms of the ease of achieving the solution)
